How the scoring is tested

The rules that turn evidence into a score are open source. We test them with property-based tests: a computer generates thousands of random projects and checks that rules a buyer relies on always hold. For example, confirming a document can never lower a score, and the JavaScript on project pages and the Python reference give the same answer. We also plant deliberate bugs in a copy of the rules to prove the tests catch them.

Method and limits

  • The six checks, verification levels and claims are defined in the fixed edition's method and in the open scoring rules (scoring.py).
  • Public information only: what a buyer could find before paying. A public document is not proof that it is genuine.
  • This page shows patterns, not single projects. Each project has its own page with its name and sourced facts.
  • Coverage is uneven: some markets have many projects and some only a few. The market tables use only markets with at least 5 projects.
  • These numbers change as the database changes. To cite a fixed figure, use the 1 November edition or note the SHA-256 shown above.

Recompute it yourself

  • bali-cases.json The full live database as JSON (the "JSON database" source above).

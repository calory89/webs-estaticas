Page weight

How many bytes a visitor downloads on our key pages, split by type, and checked against a budget every day. Heavy pages are slow pages on a hotel wifi or a phone abroad, which is where many of our buyers are.

Loading the latest run...

How it is measured

  • The same daily job that runs the visual tests loads each of the 20 key pages once on a phone (390 px) and once on a desktop (1440 px), with an empty browser cache.
  • For every request we take the bytes that actually crossed the network (compressed body plus headers, as Chrome reports them), after the network goes quiet plus 2.5 seconds, so late scripts such as analytics are included.
  • Bytes from kolaboro.com are split into HTML, CSS, JavaScript, images, fonts and other (mostly the JSON data the page reads). Everything from another host, and code Cloudflare injects under /cdn-cgi/, counts as third party.
  • Each page has a type (home, project, data, tool, content) with a budget per type and screen size. A page over budget marks the daily job as failed, which emails us. It never blocks or rolls back a deploy.
  • Lighthouse scores for the same pages, run separately every day, are on /status and in /data/lighthouse.json.

Limits

  • One load per page from one place (a build machine in the United States), measured as a first-time visitor. Visitors in Europe see the cookie banner first, and their numbers can differ.
  • Third-party vendors change what they serve without notice, so the third-party share can move from one day to the next without any change on our side.
  • Budgets were set from the first measurement on 5 November 2026. They stop pages from getting heavier; they do not say the current weight is good.

Related: real-user speed, software bill of materials (every third-party script we load), visual tests.

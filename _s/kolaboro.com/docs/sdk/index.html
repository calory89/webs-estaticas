Kolaboro / Docs / SDKs

Official SDKs

TypeScript and Python clients for the open data API. They check Kolaboro's Ed25519 signature on every answer before handing you the data, recompute Merkle proofs, and can audit the whole public log on your machine.

Not on npm or PyPI yet: install straight from kolaboro.com and compare the hash. The hashes below are read from /sdk/manifest.json and /sdk/SHA256SUMS; the button recomputes them in your browser from the files themselves.

What the client checks for you

  • Signatures. Every JSON and CSV answer of /api/open/* carries x-kolaboro-signature: Ed25519 over "kolaboro-sig-v1\n" + SHA-256(body). The client checks it against keys pinned in the package (looking up unknown key ids once at /.well-known/kolaboro-keys.json, and refusing revoked keys). A missing or wrong signature throws KolaboroSignatureError; the data is never returned.
  • Proofs. verifyProject(id) recomputes the project's leaf and Merkle path up to the daily root recorded in the public log.
  • The log. auditLog() recomputes every daily head and its link to the previous one, checks the signed checkpoint, proves every day is in the checkpoint tree, and proves each older tree is a prefix of the current one (RFC 9162 consistency).
  • The dataset. dataset() downloads /data/bali-cases.json and compares its SHA-256 with the fingerprint in a signed answer.

The verification code is not new: it is kolaboro-verify.js and kolaboro_verify.py, bundled unchanged, the same code that already checks our test vectors every day.

Options: baseUrl, verify (default true), apiKey, timeoutMs, retries (429 and 5xx, exponential backoff), fetch, publicKeys. With an API key the same calls go through the metered endpoint /api/x/k/m/*, which returns the identical signed body and counts the call against your daily quota.

Tests

Both packages are tested against production, not against mocks: signed answers, a tampered body and a stripped signature (both must be refused), filters, paging through every project, a 404, a Merkle proof, the checkpoint, a full log audit and the published test vectors.
